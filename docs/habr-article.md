# Как я сделал бесплатный двухпанельный файловый менеджер в стиле Total Commander на Electron

*Черновик для Хабра. Хабы: Open source, Разработка под Windows, JavaScript, Node.js, Программное обеспечение. Теги: файловый менеджер, Total Commander, Electron, SFTP, WebDAV, Synology, мутационное тестирование.*

**Сразу оговорка:** проект неофициальный и никак не связан с Total Commander / Ghisler Software. Это отдельная программа с MIT-лицензией.

Сайт: https://altcom.cc

## Зачем

Я привык к двум панелям и клавишам F3 / F4 / F5 / F6 / F7 / F8. На Windows это Total Commander. На macOS и Linux его нет, а привычка осталась. Делал в первую очередь для себя: чтобы один и тот же рабочий процесс работал на всех трёх системах и чтобы NAS, SSH-сервер и облака открывались как обычные папки.

## Что умеет

- Две панели, вкладки, список дисков, горячий список папок (Ctrl+D), быстрый просмотр.
- Архивы как папки: zip, 7z, tar (gz, bz2, xz), rar (только чтение), cab. Упаковка и распаковка с прогрессом, zip можно править на месте.
- Удалённые диски: Google Drive, Dropbox, Synology (в том числе через QuickConnect), SFTP с настоящей консолью, FTP/FTPS, WebDAV.
- Поиск Alt+F7: маски, регулярные выражения, текст внутри файлов и архивов, поиск дубликатов, необязательный индекс имён файлов.
- Просмотр и редактор: текст с определением кодировки, hex, картинки, PDF, видео, аудио, docx / xlsx / pptx / odf без установленного Office.
- Сравнение и синхронизация папок, групповое переименование, разрезание и склейка больших файлов (с .crc как в Total Commander), контрольные суммы, очередь заданий копирования.
- Музыкальный плеер, включая чиптюн-форматы ZX Spectrum (PT3, STC, ASC, PSG и другие).
- Восемь языков интерфейса и встроенная справка (F1) на каждом из них.
- Настройки можно синхронизировать через Dropbox.

## Устройство

Electron, чистый JavaScript, без фреймворка и без сборщика. Это сознательный выбор: исходники запускаются как есть, а отладка не требует знать, во что превратил код бандлер.

- `src/main/main.js` — главный процесс: окно, весь IPC, операции с файлами, корзина, поиск, синхронизация.
- `preload.js` — через `contextBridge` отдаёт `window.api`.
- Рендерер — обычные скрипты в общей глобальной области, порядок подключения в `index.html` важен. Класс `Panel` умеет показывать «локацию» трёх видов: локальная папка, архив как папка, удалённый диск.

### Один интерфейс для всех «дисков»

Самое полезное архитектурное решение. Клиенты Synology File Station API, SSH/SFTP (`ssh2`), FTP (`basic-ftp`), WebDAV (на голых `http`/`https` с Basic и Digest), Dropbox и Google Drive реализуют **один и тот же набор методов**: list, download, upload, mkdir, rename, delete, openDownload для потока. Панель знает только `rem.type` и вызывает общий интерфейс. Поэтому любая операция (копирование между двумя разными удалёнными дисками, просмотр, воспроизведение видео) работает для всех типов без отдельного кода, а новый тип подключается написанием одного класса.

### Медиа с удалённых дисков

Чтобы смотреть видео и слушать музыку прямо с NAS или SFTP без скачивания, в главном процессе поднят локальный стриминговый прокси. Для форматов, которые Chromium не умеет, ffmpeg (`ffmpeg-static`) на лету перекодирует видео во фрагментированный MP4, а аудио в FLAC.

### Архивы

zip читается через yauzl и пишется через yazl, а 7z, tar, cab и прочее обрабатывает `7zip-bin`. Нюанс на Windows: 7za печатает имена в кодовой странице консоли, без ключа `-sccUTF-8` кириллица ломается. rar распаковывается через `node-unrar-js`.

### Чиптюн

Декодеры PT3, STC и других форматов и эмулятор звукового чипа AY взяты из моего же проекта pt2player. Трек рендерится целиком в WAV в отдельном utility-процессе. Второй рабочий поток в главном процессе оказался в десять раз медленнее, что для меня было неожиданностью.

## Как тестировал

`npm test` запускает около 300 тестов на встроенном `node --test` за ~10 секунд. Серверы поднимаются настоящие, но локальные: `ftp-srv` для FTP/FTPS (с TLS), самописный WebDAV-сервер в памяти, mock Synology API и `ssh2`-сервер. К реальным серверам и учётным данным тесты не обращаются.

Дальше я пошёл дальше обычного покрытия строк и подключил **мутационное тестирование**: скрипт `tools/mutate.js` по одному токену портит исходники (меняет `<` на `<=`, `&&` на `||`, константы) и проверяет, что хотя бы один тест краснеет. Цель — 90 % убитых мутантов на файл. Выжившие мутанты либо показывают дыру в тестах, либо заносятся в список эквивалентных с обоснованием. Покрытие строк говорит, что код выполнялся, а мутанты говорят, что результат проверяется. На клиентах FTP и WebDAV это нашло несколько реальных пропусков.

Честно: старые части (панели, поиск, синхронизация, клиенты Synology и SSH, редактор) тестами пока не покрыты, там ручная проверка и скриптовый режим: `COMMANDER_SCRIPT=<js> npx electron .` запускает сценарий внутри страницы и делает скриншот.

## Распространение

Один сайт и одна команда `npm run release`: повышает версию, пушит, запускает сборку macOS на GitHub Actions, собирает установщик и portable exe для Windows, загружает всё на VPS с проверкой sha256 и последним шагом пишет `latest.json`. Программа сама проверяет обновления и предлагает установить. Есть заготовки для winget, Scoop, Chocolatey и Homebrew.

## Что не идеально

- Сборки пока **не подписаны**: Windows SmartScreen предупредит («Подробнее» → «Выполнить в любом случае»), на macOS нужен `xattr -cr` и разрешения на доступ к папкам.
- Electron есть Electron: памяти ест больше, чем нативный Total Commander.
- macOS и Linux проверены меньше, чем Windows. Отчёты об ошибках оттуда особенно ценны.
- Не сделано: копирование между двумя архивами, SSH-туннели, вход через ssh-agent, активный режим FTP, блокировки WebDAV.
